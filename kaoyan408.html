数据结构（45 分）
线性表 → 栈与队列 → 串 → 树与二叉树 → 图 → 查找 → 排序。算法是重中之重，综合题常要求手写代码并分析复杂度。
一、逻辑结构与存储结构
  • 逻辑结构：线性表是 n 个相同类型元素 的有限序列，除首尾外每个元素有唯一前驱和后继。
  • 顺序表：用一段连续内存存储，靠数组实现；支持随机存取（按下标 O(1)）。
  • 链表：节点通过指针链接，内存不连续；只能顺序存取（O(n) 定位）。
顺序表靠下标直取；单链表靠 next 指针逐个跳转
二、顺序表基本操作与复杂度
操作平均时间复杂度说明
按位查找 GetElemO(1)随机存取，直接下标
按值查找 LocateO(n)最坏扫描全表
插入（第 i 位）O(n)平均移动 n/2 个元素
删除（第 i 位）O(n)平均移动 (n-1)/2 个元素
易错点：插入/删除的「平均移动次数」是期望值。在等概率下，插入位置 i 有 1/(n+1) 概率，平均移动 n/2 次；删除平均移动 (n-1)/2 次。
三、单链表核心操作
  • 头插法建表：新节点插在头结点之后，生成链表逆序。
  • 尾插法建表：用尾指针 r 跟踪表尾，生成链表正序。
  • 带头结点 vs 无头结点：带头结点时第一个数据节点操作统一，首元插入/删除与中间一致，考研代码建议一律带头结点。
  • 判空：带头结点时 L->next==NULL；不带头结点时 L==NULL。
// 在带头结点单链表第 i 个位置插入 e（1-based）
int ListInsert(LNode *L, int i, ElemType e){
    LNode *p = L; int j = 0;
    while(p && j < i-1){ p = p->next; j++; }   // 找第 i-1 个节点
    if(!p) return 0;                            // i 非法
    LNode *s = (LNode*)malloc(sizeof(LNode));
    s->data = e; s->next = p->next; p->next = s; // 后插
    return 1;
}
四、双链表与循环链表
  • 双链表：每个节点有 prior 与 next，可双向遍历；删除/前插 O(1)，内存多一个指针。
  • 循环单链表：表尾 next 指向头结点，判空看是否指向自身；常设尾指针便于首尾操作 O(1)。
  • 静态链表：用数组模拟链表（游标 cur 代替指针），用于无指针语言（如早期 Fortran）；考研偶考概念。
对比一句话：顺序表「查快改慢、连续、随机存取」；链表「改快查慢、离散、顺序存取、省空间(无需预分配)但多指针开销」。
经典例题
【例题1】下列程序段的时间复杂度？ for(i=0;i<n;i++) for(j=0;j<i;j++) a[i][j]=0;
【解析】内循环次数 = 0+1+…+(n-1)=n(n-1)/2，与 n² 同阶，故 T(n)=O(n²)。本质是上三角元素个数。
经典例题
【例题2】带头结点单链表 L，将其就地逆置（不另建表），写出核心思路与复杂度。
【解析】三指针头插法：p 指向已逆转部分的头，q 指向待处理首元，r 暂存 q->next。 循环：r=q->next; q->next=p; p=q; q=r; 直到 q==NULL，最后 L->next=p。 时间 O(n)（一遍扫描），空间 O(1)（只三个指针）。
练习题
【练习题1】算法时间 T(n)=3n³+2n²+n+5，渐进复杂度是多少？
【答案】O(n³)——只保留最高次项并去掉系数。
练习题
【练习题2】顺序表与单链表在「第 1 个位置插入」和「表尾插入」的复杂度有何不同？
【答案】顺序表：第1位插入需后移 n 个元素 → O(n)；表尾若未满且已知长度 → O(1)。单链表：已知头指针头插 O(1)；表尾插入若只有头指针需走到尾 O(n)，若设尾指针则 O(1)。
一、栈（Stack）——后进先出 LIFO
  • 只允许在栈顶插入(进栈 Push)和删除(出栈 Pop)，另一端封闭。
  • 顺序栈：数组 + top 指针；top=-1 为空，top=MaxSize-1 为满。
  • 共享栈：两栈共享一维数组，栈底分别在两端，相向增长，节省空间、判满看 top1+1==top2。
  • 链栈：单链表头插实现，无栈满问题，空看 top==NULL。
栈的经典应用：① 函数递归调用（调用栈）；② 括号匹配；③ 表达式求值（中缀转后缀）；④ 迷宫/DFS 回溯；⑤ 进制转换。
二、队列（Queue）——先进先出 FIFO
  • 队尾入、队头出。顺序队易「假溢出」→ 用循环队列。
  • 循环队列：front 队头，rear 队尾下一个位置。判空 front==rear；判满 (rear+1)%MaxSize==front（牺牲一个单元区分空满）。
  • 元素个数 = (rear-front+MaxSize)%MaxSize。
  • 链队：头指针 front + 尾指针 rear，空看 front==NULL。
  • 双端队列：两端都可入出；输入受限/输出受限双端队列是选择题高频考点。
结构空条件满条件（牺牲1单元）长度
循环队列front==rear(rear+1)%m==front(rear-front+m)%m
链栈/链队top/front==NULL一般不设满遍历计数
三、栈与队列的相互实现（考过综合题）
  • 两栈实现队列：s1 负责入队，s2 负责出队；出队时若 s2 空，把 s1 全部倒入 s2（顺序反转即 FIFO）。
  • 两队列实现栈：入栈入非空队；出栈把非空队前 n-1 个移到另一队，剩最后 1 个弹出。
四、表达式求值（重点）
  • 中缀 → 后缀（逆波兰）：遇数字输出；遇运算符与栈顶比优先级，栈顶高/等则弹出，自身入栈；'(' 入栈，')' 弹到 '('。
  • 后缀求值：遇数入栈，遇运算符弹两操作数计算后压回。注意操作数顺序（先弹的是右操作数）。

经典例题
【例题1】循环队列容量 m=8，当前 front=3，rear=0，求队列长度与是否已满？
【解析】长度=(rear-front+m)%m=(0-3+8)%8=5。判满：(rear+1)%m=(0+1)%8=1≠front(3)，故未满。长度 5，还能再入 2 个（因牺牲1单元，最多存7）。
经典例题
【例题2】用栈将中缀 "3+4*2/(1-5)" 转为后缀并求值。
【解析】后缀：3 4 2 * 1 5 - / +。求值：4*2=8；1-5=-4；8/(-4)=-2；3+(-2)=1。结果=1。
练习题
【练习题1】为什么循环队列要「牺牲一个存储单元」？不牺牲能否区分空满？
【答案】若 front==rear 既表空又表满则无法区分。牺牲1单元后用「(rear+1)%m==front」判满、front==rear 判空。不牺牲也可区分：可另设 size 计数或设 tag 标记最后一次是入/出队。
练习题
【练习题2】括号串 "([)]" 是否合法？用栈说明。
【答案】不合法。栈处理：'('入、'['入；遇')'时栈顶是'['，不匹配 → 非法。正确配对须栈顶与当前右括号同类型。
一、基本概念
  • 串是字符的有限序列；空串长度 0，空格串含空格字符。
  • 串的存储：定长顺序、堆分配、块链（考研以定长/堆为主）。
二、朴素模式匹配（BF）
  • 主串 S 与模式 T 逐位比较，失配则主串指针回退到 i-j+1 重比。
  • 最坏时间 O(n·m)（n 主串长，m 模式长）。
三、KMP 算法（重点 + 高频）
  • 核心：失配时主串指针 不回退，只移动模式，靠 next 数组决定模式右滑多少。
  • next[j]：模式前 j-1 个字符的「最长相等真前后缀长度 +1」；next[1]=0。
  • KMP 时间复杂度 O(n+m)。
  • 求 next 手工步骤：写模式每位前缀，找最长相等前后缀长度 k，next[j]=k+1；next[1]=0。
模式 "ababa" 的 next 数组（下标1起）： j: 1 2 3 4 5 模式: a b a b a next: 0 1 1 2 3 （j=5: 前4位 "abab" 最长相等前后缀 "ab" 长2 → next=3）
易错：next 数组下标从 1 还是 0 起，不同教材定义不同，考试以题给定义为准。常见写法 next[1]=0，next[1..m] 共 m+1 项（含 next[0] 哨兵）。
四、nextval（优化）
  • 若 next[j] 位置的字符与第 j 位相同，可再跳过 → nextval，减少无效比较。选填可能考。
经典例题
【例题】模式串 T="ababaa"，求 next 数组（下标从1）。
【解析】逐位： j=1 a → next=0 j=2 b 前"a" 无前后缀 → 1 j=3 a 前"ab" 无 → 1 j=4 b 前"aba" 最长"a"长1 → 2 j=5 a 前"abab" 最长"ab"长2 → 3 j=6 a 前"ababa" 最长"aba"长3 → 4 next = [0,1,1,2,3,4]
练习题
【练习题】BF 与 KMP 的根本区别是什么？何时 KMP 优势明显？
【答案】BF 失配后主串回退重比，最坏 O(nm)；KMP 主串不回退、靠 next 滑动模式，O(n+m)。当主串很长、模式较短且重复前缀多（如 "aaaaab"）时 KMP 优势最大。
一、树的基本概念
  • 节点的度 = 子树个数；树的度 = 最大度。度为 m 的树第 i 层最多 m^(i-1) 个节点。
  • 节点数 n 与总度数关系：n = 总度数 + 1（每条边贡献一个度）。
  • 度为 m、有 n 个节点的树，叶子数 = n - (内部节点数)；另有公式：n₀ = 1 + Σ(i-1)·nᵢ（i 为度）。
二、二叉树性质（必背）
  • 第 i 层最多 2^(i-1) 个节点（i≥1）。
  • 深度为 k 的二叉树最多 2^k - 1 个节点。
  • 对任何二叉树：n₀ = n₂ + 1（叶子比度为2的多1个）。
  • 完全二叉树（按层填满，最后层从左连续）：节点 i 的左孩子 2i、右孩子 2i+1、父 ⌊i/2⌋。
  • 完全二叉树高度 h = ⌈log₂(n+1)⌉ 或 ⌊log₂n⌋+1。
三、三种遍历（核心中的核心）
  • 先序（DLR）：根 → 左 → 右。
  • 中序（LDR）：左 → 根 → 右。
  • 后序（LRD）：左 → 右 → 根。
  • 已知中序 + 先序/后序可唯一确定二叉树；仅先序+后序不能唯一确定。
同一棵树三种遍历结果对比（根的位置决定遍历名）
四、线索二叉树
  • 利用 n 个节点 2n 个指针域中 n+1 个空指针，指向「前驱/后继」，加速中序遍历。
  • ltag=0 指向左孩子 / 1 指向前驱；rtag 同理。
五、哈夫曼树（Huffman）
  • 带权路径长度 WPL 最小的二叉树；构造：每次取权值最小的两棵合并。
  • 应用：哈夫曼编码（前缀编码，无歧义）；WPL = Σ wᵢ·lᵢ。
  • 哈夫曼树没有度为 1 的节点，总节点数 = 2n-1（n 为叶子数）。
哈夫曼树构建：反复合并最小两权，叶子带权、内部节点为权和
// 二叉树先序遍历（递归）
void PreOrder(BiTree T){
    if(T){
        visit(T);            // 访问根
        PreOrder(T->lchild); // 左
        PreOrder(T->rchild); // 右
    }
}

【例题1】二叉树中 n₂=5，求叶子数 n₀。
【解析】由 n₀=n₂+1，得 n₀=5+1=6。叶子共 6 个。
经典例题
【例题2】已知先序 ABDECFG、中序 DBEAFCG，画出二叉树并求后序。
【解析】先序首 A 为根；中序分左(DBE)右(FCG)。左子树先序 BDE、中序 DBE → B 根，D 左、E 右。右子树先序 CFG、中序 FCG → C 根，F 左、G 右。后序：D E B F G C A。
练习题
【练习题1】度为 3 的树有 10 个节点，总度数是多少？
【答案】n = 总度数 + 1 → 总度数 = 10 - 1 = 9。
练习题
【练习题2】哈夫曼编码为什么能保证译码无歧义？
【答案】哈夫曼编码是前缀编码——任一字符的编码都不是另一字符编码的前缀，因此逐位读取时遇到完整码字即可唯一判定，不会误读。
一、基本概念
  • 完全图：无向完全图边数 n(n-1)/2；有向完全图 n(n-1)。
  • 连通图 / 强连通图；连通分量 / 强连通分量。
  • 生成树：含全部 n 顶点、n-1 条边的连通子图；最小生成树(MST)权值和最小。

三、遍历
  • DFS（深度优先）：栈/递归，类似树的先序，时间 O(n+e)。
  • BFS（广度优先）：队列，类似层序，可用于求无权图最短路径。
  • 连通图从任一点出发可遍历全部；非连通需对每个未访问点再出发。
四、最小生成树
  • Prim：从某点起，每次加「连接已选集与未选集的最小边」→ 适合稠密图。
  • Kruskal：边按权排序，依次取不形成环的最小边 → 适合稀疏图，用并查集判环。
五、最短路径
  • Dijkstra：单源最短路，权非负；每轮选距离最小且未定的点，松弛其邻边。O(n²)（堆优化 O((n+e)logn)）。
  • Floyd：多源最短路，动态规划，允许负权（无负环）。O(n³)。
  • Dijkstra 不能处理负权边，负权用 Bellman-Ford / SPFA。
六、拓扑排序与关键路径
  • 拓扑排序：AOV 网（顶点表示活动），每次删入度为 0 的点；有环则无拓扑序。
  • 关键路径：AOE 网（边表示活动），最早/最晚开始时间，差值 0 的活动在关键路径上，决定工程最短工期。
经典例题
【例题】无向图 6 个顶点、11 条边，问是否可能有？若连通最少几条边？
【解析】无向完全图最多 6×5/2=15 条边，11<15 故可能。连通最少边 = n-1 = 5（生成树）。
练习题
【练习题】Prim 与 Kruskal 的核心区别？负权边能否用 Dijkstra？
【答案】Prim 按点扩张（适合稠密），Kruskal 按边扩张（适合稀疏）。Dijkstra 要求非负权，负权会出错，应改用 Bellman-Ford/SPFA。
一、顺序与折半查找
  • 顺序查找：O(n)，对有序无序皆可，ASL=(n+1)/2。
  • 折半查找（二分）：要求有序、顺序存储；ASL ≈ log₂(n+1)-1，判定树是平衡二叉树。
二、二叉排序树（BST）
  • 左子树均小、右子树均大；中序遍历得递增有序序列。
  • 查找/插入平均 O(log n)，最坏（退化成链）O(n)。
  • 删除：叶子直接删；单孩子接上；双孩子用中序前驱或后继替换后删该节点。
三、平衡二叉树（AVL）
  • 任一节点左右子树高度差 ≤ 1（平衡因子 -1/0/1）。
  • 插入失衡用旋转调整：LL（右旋）、RR（左旋）、LR（先左后右）、RL（先右后左）。
  • ASL O(log n)，查找稳定；维护旋转有开销。
四、B 树与 B+ 树（重点，常考磁盘）
  • m 阶 B 树：根≥1 关键字，其余节点 ⌈m/2⌉-1 ~ m-1 个关键字；所有叶同层；用于文件系统/数据库索引。
  • B+ 树：关键字可能重复出现在内部与叶子；数据只存叶子，叶子用链表串起，范围查询极快；MySQL InnoDB 用 B+ 树。
  • 区别：B 树数据在各层，B+ 树数据全在叶子且叶子链化。
五、散列表（哈希）
  • 构造：直接定址、除留余数（H(key)=key mod p，p 取不大于表长的最大素数）。
  • 冲突处理：开放定址（线性探测、平方探测）、链地址法（拉链）。
  • ASL：成功/不成功分别求；装填因子 α 越大冲突越多。
  • 平方探测可避聚集，但仍可能二次聚集；链地址法简单且不要求表大小。
装填因子 α = 已存元素数 / 表长，是衡量哈希表拥挤度的关键指标，α 越大 ASL 越大。
经典例题
【例题】在关键字序列 {2,8,5,1,9,3} 上依次插入建 BST，中序遍历结果？若再插入 7 会怎样？
【解析】BST 中序必为递增：1 2 3 5 8 9（与插入顺序无关）。插入 7：5 右子树为空→7 做 5 右孩子（因 7<8 且 >5）。中序不变仍为有序。

三、关键理解
  • 快速排序：选基准 partition，递归；已近乎有序时退化 O(n²)（可用随机/三数取中缓解）。综合最快，是默认首选。
  • 堆排序：建大顶堆后反复取堆顶；O(n log n) 最坏也稳，但不稳定、缓存不友好。
  • 归并排序：分治，稳定且最坏 O(n log n)，需 O(n) 辅助空间；外排序基础。
  • 基数排序：按位（个、十、百…）分配收集，适合整数/字符串，d 趟。
选择题速记：① 平均最快=快排；② 最坏仍 O(n log n) 且原地=堆排序；③ 稳定且 O(n log n)=归并；④ 链式无法用折半/堆，但可用归并。
// 快速排序 partition（挖坑法）
int Partition(int a[], int low, int high){
    int pivot = a[low];
    while(low < high){
        while(low<high && a[high]>=pivot) high--;
        a[low]=a[high];
        while(low<high && a[low]<=pivot) low++;
        a[high]=a[low];
    }
    a[low]=pivot; return low;
}

计算机组成原理（45 分）
数据表示 → 运算 → 存储器（Cache/主存）→ 指令系统 → CPU（流水线）→ 总线 → I/O。计算量大：补码、Cache 映射、流水线时空图是综合题常客。
一、进制与编码
  • 机器数：真值加上符号位的二进制表示。
  • 原码：符号位 + 绝对值；[+0]≠[-0]。
  • 反码：正数同原码，负数原码按位取反（符号位不变）。
  • 补码：正数同原码，负数 = 反码 +1；计算机用补码做加减统一，[+0]=[-0]。
  • 求补码技巧：负数从右找第一个 1，其左全部取反（符号位不变）。
8位补码范围：-128 ~ +127 n位整数补码范围：[-2^(n-1), 2^(n-1)-1] -128 的补码 = 1000 0000（无原码/反码对应）
二、定点数与浮点数
  • 定点数：小数点固定（纯整数/纯小数）。
  • 浮点数：N = 尾数 rᵐ × 阶码 rᵉ。IEEE754：float(32位)=1符+8阶(移127)+23尾(隐含1)；double=1+11+52。
  • 阶码用移码便于比较大小；尾数用原码/补码，规格化使最高位有效。
  • 浮点溢出看阶码；上溢（阶超最大）下溢（阶小于最小，按 0 处理）。
三、溢出判断
  • 补码加减：符号位进位 Cf 与最高数值位进位 Cs，溢出 = Cf ⊕ Cs（异或）。
  • 同号相加可能溢出，异号相加不会溢出。
四、算术运算
  • 原码乘法：符号位异或，数值部分算无符号乘（移位加）。
  • 补码乘法（Booth）：处理带符号，减少操作。
  • 原码除法（不恢复余数法）、补码除法。

一、存储层次
  • 速度：寄存器 > Cache > 主存 > 磁盘 > 磁带；容量递增、速度递减、单价递减。
  • 局部性原理：时间局部性（刚访问的很可能再访问）+ 空间局部性（邻近地址很可能访问），是 Cache 存在的理论基础。
二、Cache 映射（重点）
  • 直接映射：主存块 i → Cache 行 (i mod C)。易实现、无替换算法，但冲突率高（多块争一行）。
  • 全相联：主存块可放任意 Cache 行。冲突低，但查找慢（需比对所有标记）。
  • 组相联：Cache 分组，组内全相联；主存块 → 固定组，组内任意行。折中（如 4 路组相联）。
直接映射地址拆分：Tag + 行索引 + 块内偏移

命中率 h = 命中次数 / 总访问次数 平均访问时间 Ta = h×t_cache + (1-h)×t_main CPU 时间 = (命中周期 + 失效率×失效代价) × 指令数
四、替换算法与写策略
  • 替换：随机、FIFO、LRU（最近最少用，最常用）、LFU。
  • 写策略：写直达（同时写 Cache 与主存，简单但慢）；写回（只写 Cache，换出时写回，需脏位，快）。
  • 写不命中：写分配（调入块再写）/ 写不分配（直接写主存）。
易错：Cache 总容量 ≠ 数据容量，还含标记位 + 有效位 + 脏位等额外开销；算 Cache 容量题要把这些加上。

一、CPU 基本组成
  • 运算器（ALU、ACC、PSW、通用寄存器）+ 控制器（PC、IR、MAR、MDR、时序、微操作信号）。
  • PC 取指前自动 +1（指向下一条）；IR 存当前指令；PSW 存状态标志。
二、指令周期
  • 指令周期 = 取指 + 间址 + 执行 + 中断；机器周期（节拍）是基本时间单位，时钟周期最小。
  • 1 指令周期 ≥ 若干机器周期 ≥ 若干时钟周期。

  • 段：IF 取指 → ID 译码/取数 → EX 执行 → M 访存 → WB 写回。

五段流水：第 k 周期同时有 5 条指令处于不同阶段
四、流水冲突
  • 结构冲突：硬件资源冲突（如单访存口，MEM 争用）→ 增加资源/流水线停顿。
  • 数据冲突：后续指令用到前面未写回的结果 → 转发(旁路)/停顿/重排。
  • 控制冲突：分支指令改变 PC → 分支预测 / 延迟槽。
五、性能指标
吞吐率 TP = n / T_k （n指令数，T_k总时长） 加速比 S = 非流水时间 / 流水时间 效率 E = 实际占用段-周期 / 总段-周期
易错：实际吞吐率受冲突/停顿影响，远低于理想 1/周期；算「k 条指令 t 段」总时钟数 ≈ (k+t-1)×每段周期 + 停顿。

一、总线
  • 分类：片内/系统/通信总线；数据/地址/控制总线。
  • 性能指标：总线带宽 = 总线宽度 × 工作频率 ÷ 8（Byte/s）。
  • 仲裁：集中式（链式、计数器、独立请求）/ 分布式。
二、总线定时
  • 同步：统一时钟，简单但慢设备拖节奏。
  • 异步：握手信号（不互锁/半互锁/全互锁），快慢兼容。
三、中断
  • 流程：请求 → 判优 → 响应（关中断、保护断点）→ 识别（向量）→ 服务 → 恢复 → 开中断返回。
  • 中断向量：中断服务程序入口地址；中断向量表存各向量。
  • 单重 / 多重（嵌套）中断：嵌套需更高优先级可打断当前。
  • DMA：外设直接与主存传数据，不经 CPU，由 DMA 控制器接管总线；适合高速大块传送（磁盘）。
中断 vs DMA：中断每传一个字都需 CPU 介入（保护/恢复现场开销大）；DMA 整块传送只打扰 CPU 一次（起始+结束），中间 CPU 可并行做别的。

二、信号量与 PV
  • P(S)：S--；若 S<0 则阻塞（申请资源/进入区）。
  • V(S)：S++；若 S≤0 唤醒一个等待进程（释放资源/退出区）。
  • S>0 表示可用资源数；S<0 时 |S| 表示等待进程数。
三、经典模型
  • 生产者-消费者：mutex 互斥 + empty（空缓冲数）+ full（满缓冲数）。
  • 读者-写者：允许多读、读写/写写互斥（写者优先需额外信号量）。
  • 哲学家进餐：防死锁（最多 4 人取筷 / 奇偶策略 / 同时取双筷）。
// 生产者-消费者（N个缓冲区）
semaphore mutex=1, empty=N, full=0;
Producer: P(empty); P(mutex); 放入; V(mutex); V(full);
Consumer: P(full); P(mutex); 取出; V(mutex); V(empty);
顺序铁律：先 P(empty/full) 等资源信号量，再 P(mutex) 进临界区；V 顺序随意但成对。把 mutex 放最前可能死锁（缓冲满时生产者在 mutex 内等 empty，消费者进不了临界区释放）。
经典例题
【例题】用 PV 实现「两个进程互斥访问临界区」，各用一个信号量。
【解析】设 semaphore mutex=1。 进程A：P(mutex); 临界区; V(mutex); 进程B：P(mutex); 临界区; V(mutex); mutex=1 保证同时仅一个进入。若一方在临界区，另一方 P(mutex) 后 mutex=0→-1 阻塞，直到对方 V 唤醒。
练习题
【练习题】生产者消费者中若把两个 P 操作顺序颠倒（先 P(mutex) 再 P(empty)）会怎样？
【答案】可能死锁。当缓冲区满，生产者先 P(mutex) 拿到锁，再 P(empty) 阻塞在临界区内；消费者因拿不到 mutex 永远无法进入取走产品，双方僵持。
一、四个必要条件
  • 互斥、占有并等待、不可剥夺、循环等待——四个同时成立才死锁。
二、处理策略
  • 预防：破坏任一必要条件（如一次性分配资源破坏「占有等待」）。
  • 避免：银行家算法，分配前判断是否进入安全状态。
  • 检测与解除：资源分配图（死锁定理：无环则无死锁）、剥夺/回滚/终止进程。

三、银行家算法
  • 核心：Request ≤ Need 且 ≤ Available 才试分配，检查分配后是否存在安全序列（能使所有进程按序完成）。
  • 安全序列：存在一种推进顺序，每步可用资源都能满足某进程最大需求。
易错：「安全状态」一定无死锁；「不安全状态」不一定死锁，只是有风险。银行家算法拒绝的是「会导致不安全」的请求。
经典例题
【例题】死锁四个必要条件中，哪一个最容易通过「资源一次性分配」破坏？
【解析】破坏「占有并等待」：要求进程运行前一次性申请全部所需资源，拿到后才运行；运行期间不再持有部分资源去等别的，从而消除「占有且等待」。代价是资源利用率低、可能饥饿。

一、连续分配 vs 离散分配
  • 连续：单一/固定/可变分区，有外部碎片。
  • 离散：分页（物理单位，无外碎、有内碎）、分段（逻辑单位，无内碎、有外碎）、段页式。
二、分页存储
  • 逻辑地址 = 页号 P + 页内偏移 W；页表映射 P→物理块号。
  • 地址转换：P 查页表得块号 f，物理地址 = f×页大小 + W。
  • 快表 TLB：缓存近期页表项，命中则免访存页表。
逻辑地址 32 位，页大小 4KB(2^12) → 页号占 20 位，页内 12 位 物理地址 = 块号(块大小=页大小) × 页大小 + 页内偏移
分页地址转换：页号查页表得块号，页内偏移直接拼接
缺页处理：查页表未命中 → 缺页中断 → 调页入内存 → 更新页表 → 重新执行指令
三、分段与段页式
  • 分段：地址 = 段号 + 段内偏移，段长可变，便于保护与共享（如代码段只读）。
  • 段页式：先分段再每分段页，兼两者优点，地址转换多一步。
四、虚拟内存
  • 基于局部性，用辅存作扩充；只把部分页/段装入。
  • 缺页中断：访问页不在内存 → 调页（可能需页面置换）。
    • FIFO 按进入先后淘汰，可能 Belady 异常（帧增多缺页反增）；LRU 按最近访问时间淘汰，更贴局部性
  • 页面置换算法：OPT（理想）、FIFO（可能 Belady 异常）、LRU、Clock（二次机会）、LFU。
  • 抖动（thrashing）：缺页率过高，CPU 忙于换页。
易错：① 页是物理划分、段是逻辑划分；② LRU 近似 OPT 但实现贵，Clock 是常用折中；③ FIFO 的 Belady 异常指「分配页数增多反而缺页次数上升」。
经典例题
【例题】页大小 4KB，逻辑地址 0x1A2B，页表映射页号 6→块号 9。求物理地址（十六进制）。
【解析】4KB=2^12，低12位为页内偏移。0x1A2B=0001 1010 0010 1011，页号=高20位中的低部分：1A2B>>12=1，偏移=2B。页号1→块9。物理地址=9×4096+0x2B=0x9000+0x2B=0x902B。
练习题
【练习题】LRU 与 Clock 各有什么优缺点？FIFO 为什么会有 Belady 异常？
【答案】LRU 命中率高但需维护访问顺序（硬件/栈实现贵）；Clock 用访问位近似 LRU，开销小。FIFO 只按入队顺序换出、不反映使用频度，故增加页框反而可能换掉马上要用的页，导致缺页增多（Belady 异常）。

  • 路由表：目的网络、下一跳、出接口、度量。
  • 静态路由 vs 动态路由（RIP 距离矢量、OSPF 链路状态）。
  • 最长前缀匹配：目的 IP 与多条路由匹配时取掩码最长者。
四、IP 数据报与分片
  • 首部含版本、总长度、标识、标志、片偏移、TTL、协议、校验和。
  • MTU 限制 → 分片；片偏移以 8 字节为单位；MF=1 表示还有分片。
易错：① 子网「可用主机数 = 2^主机位 - 2」（去网络/广播）；② 给定 IP/掩码求网络号必做按位与；③ 分片偏移单位是 8 字节，算实际偏移要 ×8。
经典例题
【例题】主机 192.168.1.130/26，求所在子网网络号、广播地址、可用主机范围。
【解析】/26 掩码 255.255.255.192，块大小 64。130 落在 .128~.191 块 → 网络号 192.168.1.128；广播 192.168.1.191；可用 .129~.190。
练习题
【练习题】ARP 工作在哪一层？为什么不直接用 MAC 通信而需要 IP？
【答案】ARP 属网络层（但涉链路）。IP 提供全局逻辑寻址、跨网络路由；MAC 仅本地链路寻址。分层后上层用统一 IP 通信，下层各异的 MAC 由 ARP 在本地适配，解耦网络技术与端到端寻址。
一、UDP vs TCP
UDPTCP
连接无连接面向连接
可靠不可靠、尽力交付可靠、确认重传
顺序不保证按序、无重复

二、TCP 首部关键字段
  • 端口（源/目的）、序号 seq、确认号 ack、窗口（流量控制）、标志位（SYN/ACK/FIN/RST/PSH/URG）。
  • 序号 = 本报文段首字节在数据流中的位置；确认号 = 期望收到的下一字节。
三、三次握手与四次挥手
  • 三次握手：SYN → SYN+ACK → ACK，双方确认彼此收发能力，同步初始序号。
  • 四次挥手：FIN → ACK → FIN → ACK（全双工，各自关闭方向）。
  • TIME_WAIT 等 2MSL，确保最后 ACK 到达、旧报文消亡。
三次握手：各自确认对方的收发能力与初始序号
滑动窗口：未确认报文留在窗内，收到 ACK 窗口整体右滑；rwnd 由接收方通告实现流量控制
四、可靠传输与拥塞控制
  • 可靠：序号、确认、超时重传、滑动窗口。
  • 流量控制：接收窗口 rwnd 防发送方淹没接收方。
  • 拥塞控制：慢开始（指数增 cwnd）、拥塞避免（线性增）、快重传、快恢复；ssthresh 为阈值。
cwnd 增长：慢开始指数到 ssthresh 后转为线性增加
易错：① 握手为何三次而非两次——防止已失效的连接请求突然又传到服务器造成误建；② 流量控制防「接收方来不及」，拥塞控制防「网络堵」，两者目标不同；③ ack = 期望下一字节，不是已收到的最后一字节。
经典例题
【例题】为什么 TCP 建立连接要三次握手而不是两次？
【解析】两次握手时，若客户端早前发的失效 SYN 延迟到达服务器，服务器会误以为新连接并分配资源、发 ACK，但客户端并不认，造成服务器空等浪费。三次握手中第三步让服务器确认客户端确实要建连，避免半开连接。
练习题
【练习题】TCP 流量控制和拥塞控制分别解决什么问题？窗口来源有何不同？
【答案】流量控制防止发送方速率超过接收方处理能力，窗口来自接收方 rwnd；拥塞控制防止注入过多数据压垮网络，窗口来自动态 cwnd（基于网络拥塞反馈）。最终发送窗口 = min(rwnd, cwnd)。
一、DNS（域名系统）
  • 域名 → IP 的分布式数据库；递归+迭代查询结合。
  • 解析过程：浏览器缓存 → 本地 hosts → 本地 DNS → 根 → 顶级域 → 权威服务器。
  • 记录：A（域名→IPv4）、AAAA（→IPv6）、CNAME（别名）、MX（邮件）。
二、HTTP
  • 请求/响应模型，默认 80 端口；HTTP 无状态，靠 Cookie/Session 保持。
  • 方法：GET（取资源）、POST（提交）、HEAD 等。
  • HTTP/1.0 非持久（每对象建连）、1.1 持久连接（管线化）；HTTPS = HTTP+TLS 加密。
  • 状态码：2xx 成功、3xx 重定向、4xx 客户端错（404）、5xx 服务端错。
三、FTP / Email / DHCP
  • FTP：控制连接(21)+数据连接(20)，双连接。
  • Email：SMTP（发，推）、POP3/IMAP（收，拉）。
  • DHCP：自动分配 IP（DORA 四步）。
四、P2P 与 CDN
  • P2P：对等共享（BitTorrent），非中心服务器，扩展性好。
  • CDN：内容分发网络，就近缓存加速。
易错：HTTP 本身无状态，状态由 Cookie 维持；DNS 通常用 UDP 53（查得快），区传送用 TCP；HTTPS 加密的是 HTTP 报文而非 IP。
经典例题
【例题】浏览器输入 www.xxx.edu.cn 回车到显示页面，简述涉及的应用层协议。
【解析】① DNS 解析域名→IP（UDP）；② 建立 TCP 连接（三次握手，涉及 TCP）；③ HTTP 请求页面（HTTP/HTTPS）；④ 若含图片再发多次 HTTP 请求；⑤ 可能 DHCP 获取本机 IP（若未配）。核心：DNS + TCP + HTTP。
练习题
【练习题】HTTP 是无状态的，为何登录后服务器能认出你？
【答案】靠 Cookie：首次登录服务器在响应中下发 Set-Cookie（含会话标识），浏览器保存并在后续请求自动带上 Cookie，服务器据此查 Session 识别用户，从而在无状态的 HTTP 上维持登录态。

【变式1】用两个无重复单链表 L1、L2 表示集合，求交集存入新表，写核心思路与复杂度。

【变式2】如何用一个栈判断字符串是否为回文（忽略非字母）？
【答案】把字符依次压栈，再顺序遍历原串与逐个出栈字符比较，全部相等即回文；或只压前半、与后半比对。关键是用栈实现「逆序对照」。
练习题
【变式3】模式串 "ababa"，求 nextval 数组（下标从 1）。
【答案】next=[0,1,1,2,3]；nextval：j=1 得 0；j=2(b) 指向 next=1(a) 不同 → 1；j=3(a) 指向 1(a) 相同 → 取 nextval[1]=0；j=4(b) 指向 2(b) 相同 → nextval[2]=1；j=5(a) 指向 3(a) 相同 → nextval[3]=0。故 [0,1,0,1,0]。
练习题
【变式4】完全二叉树有 1000 个节点，求高度与叶子数。
【答案】高度 h=⌊log₂1000⌋+1=10（2⁹=512<1000≤1024）。前 9 层满共 511 节点，第 10 层 489 节点；第 9 层 256 节点中作为父节点的有 ⌈489/2⌉=245 个，故叶子=256-245+489=500。
练习题
【变式5】为什么 Dijkstra 不能处理负权边？举反例。
【答案】Dijkstra 一旦选定距离最小点就永久定稿、不再更新；若有负权，后面可能出现更短路径却无法回溯修正。反例：A→B=1，A→C=4，C→B=-2。从 A 先定 B=1（错），实际 A→C→B=2 更短但 B 已定稿。
练习题
【变式6】线性探测开放定址，装填因子 α=0.75，成功/不成功 ASL 量级？
【答案】线性探测成功 ASL≈½(1+1/(1-α))=2.5；不成功 ASL≈½(1+1/(1-α)²)=8.5。可见 α 越大、不成功查找越慢。
练习题
【变式7】对「基本有序」序列，快排与直接插入谁更优？为什么？
【答案】直接插入更优。基本有序时插入比较/移动极少，近 O(n)；快排以首元素为基准会退化成 O(n²)（近乎有序恰是其最坏情况），除非用随机/三数取中缓解。

【变式1】8 位补码中 -128 没有对应原码/反码，机器里如何表示？怎么得到？
【答案】规定 1000 0000 即 -128 的补码（由 0-128 或模 2⁸ 溢出得到）。它独占补码下界，无法用「取反加一」逆推原码（会溢出），属补码特例。
练习题
【变式2】写回法一致性比写直达差，为何仍常用？何时必须写直达？
【答案】写回只在换出时写主存，访存少、速度快，适合写密集。但当多处理器共享内存或 DMA 直接读主存时，写回会造成主存与 Cache 不一致，此时需写直达或 MESI 等一致性协议。

【答案】① 必须等当前指令执行完（不能指令中途响应）；② 关中断时段；③ 中断优先级判优；④ 保护现场与取向量开销。最长延迟≈最长指令周期 + 现场保护时间。

练习题
【变式1】线程切换为何比进程切换快得多？
【答案】同进程线程共享地址空间与资源，切换只需换寄存器/栈/PC，不换页表、不刷 TLB；进程切换要换地址空间并刷新 TLB，开销大得多。
练习题
【变式2】多级反馈队列里，一个长作业会被怎样对待？
【答案】从高优先级队开始，用完时间片未完则降级到下一队列，越往后时间片越长。长作业逐渐沉到低队列，不饿死但响应变差；短交互任务始终在高队列获快速响应。
练习题
【变式3】读者-写者若要求「写者优先」，关键怎么做？
【答案】引入写者计数与额外信号量：只要有写者等待，就用进入临界信号量阻塞新读者，保证写者尽快拿到独占权，避免写者被持续涌入的读者饿死。
练习题
【变式4】进程 P1(最大7,已分配4)、P2(最大5,已分配2)、P3(最大4,已分配3)，可用资源 2，是否安全？
【答案】Need：P1=3,P2=3,P3=1。先满足 P3(需1≤2)→回收3→Avail=5；再 P1(需3≤5)→Avail=8；再 P2(需3≤8)。存在序列 P3,P1,P2 → 安全，不会死锁。

【变式5】快表命中率从 98% 降到 90%（内存 100 周期、TLB 1 周期、无缺页），EAT 变化多少？
【答案】98%：0.98×101+0.02×201=103；90%：0.9×101+0.1×201=111。EAT 由 103 升到 111，约 +7.8%，命中率下降明显拖慢访存。

【变式6】访问串 1,2,3,4,1,2,5,1,2,3,4,5，物理块 3，LRU 与 FIFO 各缺页几次？
【答案】LRU：模拟得缺页 10 次（仅最后的 5 命中一次）。FIFO：缺页 9 次。可画栈/队列逐步验证；注意此串下 FIFO 未发生 Belady 异常。

【答案】段是逻辑单位（如代码段、数据段），可按段设读/写/执行权限并整段共享；分页按固定页框划分，一页常混合多段内容，难以按语义共享与保护。

【变式1】协议三要素「语法、语义、时序」各指什么？
【答案】语法=数据格式与编码（怎么表示）；语义=控制信息的含义与应做的动作（做什么）；时序=事件发生的顺序与速度匹配（何时做、按什么节奏）。

【答案】取较小者。奈奎斯特=2×4000×log₂8=24000 bps；香农=4000×log₂(1+100)≈26640 bps。受 8 电平码元限制，奈奎斯特更紧，故上限 24000 bps。

【变式3】CRC 能否 100% 检错？它主要靠什么？
【答案】不能 100%（理论上仍有极小漏检概率，取决于生成多项式）。CRC 靠模 2 除法余数，能检测所有单位/双位错、奇数位错及大部分突发错，是链路层主流检错手段（检错重传，不纠错）。

【答案】两网第三字节为 0000 1010(10) 与 0000 1011(11)，仅最低位不同 → 可聚合为 202.113.10.0/23（掩码 255.255.254.0），覆盖 .0~.255 两个 C 段。

【变式5】RIP 与 OSPF 各属哪类路由算法？优缺点？
【答案】RIP 距离矢量，简单、收敛慢、跳数≤15、易计数到无穷；OSPF 链路状态，用 Dijkstra 算最短路，收敛快、无跳数限制、适大网，但实现复杂、开销大。
练习题
【变式6】TCP 主动关闭方为何要有 TIME_WAIT（2MSL）？
【答案】① 确保最后 ACK 能到达被动方（若丢失对方重发 FIN，可再回 ACK）；② 让本连接残留报文在网络中消亡，避免新连接误收旧数据。故等待 2MSL。
练习题
【变式7】递归查询与迭代查询在 DNS 中如何配合？
【答案】主机→本地 DNS 通常用递归（本地全权代查）；本地 DNS→根/顶级/权威 用迭代（每层只回下一步该问谁），减轻根服务器负担；最终结果由本地 DNS 回主机。

综合题 1（数据结构 + 组成原理）：Cache 与查找

某机字长 32 位，主存按字节编址，Cache 容量 16KB、块大小 32B、4 路组相联。问：(1) 地址各字段位数；(2) 主存地址 0x1234 命中哪一组；(3) 若顺序访问数组 int a[4096]，分析 Cache 命中率趋势。
解答：(1) 块内 5 位(log₂32)；组数 = 16KB/(4×32B)=128 组 → 组索引 7 位；地址按 32 位算 Tag=32-7-5=20 位。 (2) 0x1234=0001 0010 0011 0100，低5位=10100(偏移)，次低7位=010 0011→组号 0x23=35，故命中第 35 组。 (3) 数组 int 占 4B，一行 8 个 int 恰 32B=1 块；顺序访问时每 8 个元素仅 1 次缺失，命中率≈7/8，体现空间局部性。若跨行 stride 大则命中率下降。

综合题 2（操作系统 + 组成原理）：虚拟内存与 TLB

页大小 4KB，页表驻留内存，TLB 命中率 98%、访问 1 周期，内存访问 100 周期。求有效访问时间(EAT)。若引入快表后缺页率 0.1%、缺页处理 10⁶ 周期，EAT 变为多少？
解答：无缺页时 EAT = 0.98×(1+100) + 0.02×(1+100+100) = 0.98×101 + 0.02×201 = 98.98 + 4.02 = 103 周期。 含缺页：EAT = 0.999×[0.98×101 + 0.02×201] + 0.001×(10⁶+200) ≈ 0.999×103 + 1000.2 ≈ 102.9 + 1000.2 ≈ 1103 周期。可见缺页代价远大于 TLB/访存。

综合题 3（计网 + OS）：TCP 拥塞与调度

简述 TCP 慢开始阶段 cwnd 增长规律；若某连接 RTT=100ms、初始 cwnd=1 MSS、ssthresh=16，经过 5 个 RTT 后 cwnd 为多少（假设无丢包）？并说明与进程调度中「时间片」概念的异同。
解答：慢开始：cwnd 每收到一个 ACK 翻倍（每个 RTT 翻倍）。cwnd: 1→2→4→8→16→32，但到 16 触及 ssthresh 后转入拥塞避免（线性+1）。故 5 个 RTT：RTT1=2, RTT2=4, RTT3=8, RTT4=16(到达阈值转避免), RTT5=17。最终 cwnd=17 MSS。 与时间片：都属「资源配额」思想——时间片限制单进程占用 CPU 时长，cwnd 限制单连接注入网络的数据量；不同在于时间片由调度器硬性轮换，cwnd 由网络反馈动态调整。
